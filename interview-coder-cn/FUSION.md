# 截屏解题助手 2.2.2 融合版

本版以仓库中用户修改版 2.1.15 的完整源工程为基础，保留原有功能，重整 Windows 采集与窗口稳定性。面灵安装包只用于行为分析参考，本工程没有嵌入其可执行文件、前端资源、账号或服务接口。

## Windows 使用

仓库的 [Windows 自动构建](https://github.com/Zachary-check/cloud/actions/workflows/fusion-windows.yml) 页面提供运行包：登录 GitHub，打开最新成功的构建，在 Artifacts 中下载 `interview-coder-cn-2.2.2-fusion-win-x64`。下载得到的 ZIP 可以直接完整解压运行。构建附件保留 30 天，可通过重新构建刷新。

1. 将 `interview-coder-cn-2.2.2-fusion-win-x64.zip` 完整解压到一个目录，运行其中的 `截屏解题助手.exe`。不要只移动 EXE；`resources/native` 中两个组件须随整个目录保留。
2. 在「设置 → AI 设置」填写自己的 API Base URL、API Key 和模型名。备用模型仍可只填写模型名，或单独填写另一套端点与 Key；本版不需要面灵账号。
3. 「截图与客户端兼容」默认自动识别。也可以明确选择通用、时习知、国考云、易考锁屏客户端，并选择题目所在显示器。
4. 正常使用原有快捷键、悬停工具条、追加截图和追问。黑屏或读取失败会自动尝试其他通道；仍失败时不向 AI 提交该截图。
5. 易考锁屏等场景可在设置中点击「打开原生笔试窗」。原生窗提供截题、加页、复制、停止、翻页、收起与退出；悬停停留或点击按钮均可操作。退出原生窗会回到工作台，完整设置、语音、知识库与追问保留在工作台。
6. 「纯文字答案」默认开启，主工作台和原生笔试窗均使用真正透明的答案背景。Windows 本地小画面采样选择黑字或白字，主工作台文字有细微阴影以帮助识别；设置页与对话框保持正常背景。关闭此选项可恢复面板背景。背景复杂时自动字色无法保证每个位置都有同样对比度。
7. 「显示截图缩略图」默认关闭，不生成或展示预览；开启后从下一次截图开始展示。这个开关不影响发给 AI 的完整截图，也不影响截图自动保存。

平台预设、共享表面和原生窗口属于兼容能力，效果依赖 Windows、显卡、权限与考试客户端版本。Windows 自动构建还会检查原生组件启动、背景采样协议、原生窗批量答案更新与退出，以及 Electron 界面和图像线程。本次未在真实考试客户端中实测，不承诺所有锁屏或捕获保护均可兼容。

## 2.2.1 的性能与稳定性修复

- 全屏 PNG 编码、备用通道 PNG 解码和可选缩略图在独立线程执行；像素缓冲区转移给线程，避免主线程复制并压缩整屏图像。处理支持取消、超时和异常后重建，截图期间不再暂停工具条指针轮询。
- 常规截图不再强制合成所有分层窗口，减少额外的桌面合成工作；特殊窗口仍沿用各自的采集与回退通道。
- 原生进程的发送队列和 GUI 更新队列都只保留最新状态，防止流式答案积压导致内存持续增长。
- 在截图阶段点击停止会取消整个请求；晚到的截图不会启动 AI。新请求开始后，旧请求退出不能结束新请求的加载状态。
- 修复原生窗口关闭后立即重开的状态竞争；桌面切换后建窗失败会结束原生进程并返回工作台；禁用悬停触发时原生窗也遵守该设置。
- 主窗口销毁或退出时取消未完成请求，避免向已销毁的窗口继续发送答案。

## 2.2.2 的工具栏修复

- 工具栏背景跟随「纯文字答案」，并单独采样工具栏下方的背景来选择图标颜色。
- 工具栏图标保持完整不透明度，答案窗口仍可用原有设置、快捷键和按钮调节透明度。设置同步不再反复写工具栏的 Windows 整窗透明度。
- 修复 `#toolbar` 与 `#/toolbar` 地址识别不一致：两种地址下，工具栏都只读取自己的配置，不回写独立存储副本、不注册主窗口快捷键。
- 工具栏可见时定期提交小范围重绘，隐藏后停止；不因此改变焦点、位置或置顶顺序。图标颜色即时切换，避免过渡期间变灰。
- 系统暂时返回空屏幕区域时保留正常工具栏尺寸，恢复后重新定位；不会把工具栏压成 1×1 像素。
- 窗口闲置后变淡的现象仍需在用户电脑上复核；本次覆盖了代码中已识别的自动设置回写和透明窗口绘制路径。

## 保留的原有能力

- 笔试、面试、双机位三种工作模式；截图、多图连续上下文、手动追问、停止与流式答案。
- 自定义 AI 端点、Key、模型和备用模型；首字超时、取消和失败切换规则。
- 场景提示词、代码语言偏好、语音转录、面试知识库、项目限定规则。
- 面试记录、记录命名与保存、截图保存、音频设备、快捷键、鼠标穿透、透明度、悬停工具条与窗口位置恢复。

## 新增与修复

| 模块         | 行为                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| 本地平台识别 | 精确匹配有资格的窗口进程；手动选择优先。窗口快照只用于本地选路            |
| 时习知       | Windows 11 且能力满足时优先 GPU 子窗口；否则共享表面                      |
| 国考云、易考 | 优先共享表面；按可用能力尝试子窗口、窗口绘制和常规截图                    |
| 图像诊断     | 全黑、内嵌大黑矩形检查；不将无法读取的题目误当作已成功重构                |
| 调度         | 工作路径的会话缓存、失败失效、过期结果隔离、取消、超时和临时文件清理      |
| 原生答题窗   | 独立 Win32 进程，尝试随输入桌面变化重建窗口，沿用主程序的 AI 与截图工作流 |
| 窗口稳定性   | 避免同步拒绝置顶时的事件递归；工具条不会用旧的独立设置副本覆盖主窗口      |
| 数据边界     | Key 留在主程序；原生进程只收到必要系统环境变量，诊断不含图片或 API Key    |

`capture.log` 位于应用用户数据目录，记录采集方式、结果和耗时。设置页「刷新诊断」可查看本次各路径的尝试结果。没有成功截图时，上层请求不会进入图文 AI 流程；这不代表外部模型服务具有任何计费豁免承诺。

## 源码结构

```text
src/shared/capture.ts             类型、设置规范化和平台策略
src/main/capture/quality.ts       BGRA 画面诊断
src/main/capture/service.ts       采集回退、缓存与取消
src/main/capture/native-backend.ts 原生帧协议与文件边界校验
src/main/capture-controller.ts    Electron 入口、诊断和兼容降级
src/main/native-overlay.ts        原生显示进程与答案事件
native/src/capture.cpp            Windows 采集助手
native/src/overlay.cpp            Win32 答题窗口
```

原生助手采用 GDI、DWM 共享表面/D3D11、子窗口候选和 PrintWindow 等路径，不依赖 Node 原生扩展、管理员提权、驱动或远程私有服务。不能读取的纹理、窗口和格式会进入失败与回退处理。

## 构建

Node.js 22 或更新版本：

```sh
npm ci
npm test
npm run lint
npm run build
npm run build:win
```

源码附带这次编译的 Windows x64 原生组件，正常打包无需再安装 C++ 工具链。修改原生代码后，用 Zig 0.13 重建：

```sh
# 将 zig 放入 PATH，或设置 ZIG_EXE 为其绝对路径
npm run build:native
```

Linux 交叉构建同样可生成 Windows ZIP。`npm test` 包含 90 分钟音频的合成样本验证，通常比其余测试耗时更长。Windows API 与实际客户端兼容性须在 Windows 上进一步验证。
